# Jira 일감 목록 화면 (Neovim) 설계

2026-11-25. 상태: 승인 대기.

## 1. 의도

사용자의 말: "UI가 너무 단순해서 사용이 불편하다. 선택할 수 있는 것을 제안해 주지 못하고 암기할 것이 많다. Jira 이슈들을 보는 것도 어렵다."

지금 Neovim에서 일감을 보려면 키를 이미 알아야 한다. 목록은 Obsidian(`jira/_views/일감.base`)에만 있다.
이 작업은 **일감을 훑고, 거르고, 고르는 화면**을 Neovim에 만든다. 고른 일감에 기존 동작(댓글·전환·담당·워크로그)을 바로 건다.

사용자가 승인한 순서: 1단계 보기(이 문서) → 2단계 쓰기(새 일감 양식, 후보 제안. 따로 설계한다).

## 2. 목표·비목표·실패 조건

목표
- 키를 외우거나 치지 않고 일감을 찾아 연다.
- 목록은 네트워크 없이 즉시 뜬다(캐시만 읽는다).
- 거르기 값(상태·프로젝트·담당·저장된 뷰)은 목록에서 고른다. 직접 치지 않는다.
- 목록의 줄에서 기존 Jira 동작이 그대로 동작한다.

비목표 (2단계 또는 하지 않음)
- 새 일감 양식, 유형·우선순위·담당자 후보를 Jira에서 받아 오기.
- 라이브 JQL 결과를 이 화면에 그리기(`q`는 지금 그대로).
- 일감 항목 편집.
- fzf-lua 등 새 플러그인을 필수로 만들기.

실패 조건 (동작해도 실패)
- 목록을 열 때 Jira에 접속하거나 눈에 띄게 기다린다.
- `jira/` 파일을 고친다. 목록은 읽기만 한다.
- Lua가 front matter를 따로 해석한다(Python과 어긋난 사례가 많았다: C-12, C-13, C-23).
- 화면 없는 Neovim에서 멈춘다.

## 3. 제약

- Neovim 0.12, Windows, Python 3.14. 명령줄은 ASCII, 인수는 `--argv-stdin`(D10).
- `KB_AGENT=1`에서도 읽기 명령은 허용한다. 새 명령은 읽기 전용이다.
- 표시 폭은 한글을 고려한다(`strdisplaywidth`).
- 일감 수에 상한은 없다(`max_results`는 쪽 크기이고, 완료 일감은 `jira/`에 계속 남는다). 수천 줄은 버퍼에 그대로 그린다. 가상 스크롤은 만들지 않는다. 5,000건으로 그리기 시간을 시험한다.
- 문서·명령 목록 일치 시험(`tests/test_docs.py`)과 저장소 구조 시험(`tests/test_repo_tree.py`)을 지킨다.

## 4. 접근 방식

| 안 | 내용 | 장점 | 단점 |
|---|---|---|---|
| A (선택) | 전용 목록 버퍼 + Python 읽기 명령 `kb.py issues --json` | 의존성 없음. 헤드리스 시험 가능. 기존 `results.lua`·`jira.lua`를 그대로 씀. 해석은 Python 한 곳 | 퍼지 검색은 없음(`/`와 거르기 키로 대신) |
| B | fzf-lua 선택 창에 동작 키를 붙임 | 퍼지 검색이 좋음 | fzf-lua는 선택 사항이라 A가 어차피 필요. 여러 열·거르기 상태 표시가 약함. 시험이 어려움 |
| C | Lua가 `jira/*.md` front matter를 직접 읽음 | Python 변경 없음 | 해석기가 둘이 됨. 이 저장소가 반복해서 겪은 불일치 |

선택: A. 사용자가 방식을 맡겼고("승인"), 이 저장소의 원칙(의존성은 선택, 해석은 Python)에 맞는다. B는 나중에 A 위에 "fzf로 고르기" 키 하나로 얹을 수 있다.

## 5. 설계

### 5.1 Python: `kb.py issues`

읽기 전용 새 명령. `jira/*.md`의 front matter를 읽어 목록을 낸다(스텁과 `jira/_views/`는 제외).
`jira_sync._disk_records`는 그대로 못 쓴다: 8개 항목만 돌려주고, 범위 밖 일감을 버리고, 깨진 파일을 말없이 건너뛴다(`jira_sync.py:543-547`). 새 읽기 함수를 만들고 front matter 해석은 `lib.frontmatter`를 쓴다.

```
python scripts/kb.py issues --json [--all] [--view NAME]
```

- 기본: `in_scope: false`가 아닌 일감 전부(완료 포함). 거르기는 편집기가 한다.
- `--all`: 범위 밖 일감도 포함(행에 `in_scope: false`).
- `--view NAME`: `jira/_views/NAME.md` 표의 키만, 그 순서로. 없는 뷰는 종료 코드 1과 뷰 이름 목록.
  - 뷰는 범위와 무관한 JQL이라 `jira/KEY.md`가 없는 키가 섞일 수 있다(`jira_sync.py:495`). 파일이 있으면(범위 밖이어도) 그 파일의 온전한 행을 낸다. 파일이 없거나 스텁이면 뷰 표의 값(키·제목·상태·담당·마감·갱신)만 채우고 `"cached": false`를 붙인다. 나머지 항목은 빈 값이다.
- 출력은 JSON 객체 하나:

```json
{"synced_at": "2026-11-25T09:10:00+09:00",
 "views": ["today", "blocked", "review"],
 "issues": [{"key": "KB-12", "project": "KB", "summary": "…", "status": "진행 중",
             "status_category": "indeterminate", "issuetype": "Task", "priority": "High",
             "assignee": "김철수", "sprint": "…", "labels": [], "components": [],
             "updated": "…", "due": "2026-11-28", "url": "…"}]}
```

- `synced_at`은 `.state/sync.json`의 `last_sync`(없으면 null). 일감 하나만 받는 `sync --key`는 이 값을 바꾸지 않는다. 머리줄의 시각은 "마지막 전체·증분 동기화"를 뜻한다.
- front matter가 깨진 파일은 건너뛰고 stderr에 한 줄 남긴다. 종료 코드는 0.
- `--json` 없이 부르면 사람이 읽는 표(키·상태·제목·담당·마감).
- `kb.py serve`의 처리 목록에 넣는다(읽기, 잠금 없음). `AGENTS.md`의 허용 명령에 넣는다.

### 5.2 Neovim: 목록 버퍼 `*work-kb-issues*`

새 모듈 `nvim/lua/work-kb/issues.lua`. 열기: `<leader>kJ`, `:WorkKb issues`, Jira 메뉴의 `l`.

```
 Jira 일감  [미완료]  프로젝트: 전체  담당: 전체  뷰: —   23/41건   동기화 09:10
 ──────────────────────────────────────────────────────────────────────────
 KB-12   진행 중   High  배포 스크립트 롤백 처리        김철수   11-28
 KB-31   할 일     —     캐시 무효화 설계              홍길동   11-30
 OPS-40  막힘      High  인증서 갱신                   홍길동   —
 ──────────────────────────────────────────────────────────────────────────
 <CR> 열기  p 미리 보기  s 상태  P 프로젝트  A 담당  V 뷰  x 거르기 지움  g? 도움말
```

- 읽기 전용 스크래치 버퍼. 현재 창에 연다(이미 보이면 그 창으로 간다).
- 각 줄은 맨 키로 시작한다. 그러나 동작에는 **키를 명시해서 넘긴다**. `jira.key_at_point`는 커서 밑의 것을 먼저 보므로(`jira.lua:131-140`), 제목에 다른 키가 있으면 엉뚱한 일감을 잡는다.
- 그래서 `jira.lua`를 조금 고친다: `comment`·`transition`·`assign`·`worklog`·`view`가 선택 인수 `opts = { key = , initial = , on_done = function(code) end }`를 받는다. 인수가 없으면 지금과 똑같이 동작한다. `sync`도 `on_done`을 받는다.
- 목록에서 부른 댓글의 기본 본문은 **빈 글**이다(`initial = ""`). 지금처럼 현재 줄을 넣으면 목록의 줄 글이 댓글로 나갈 수 있다.
- 열: 키, 상태, 우선순위, 제목, 담당, 마감. 제목은 창 폭에 맞춰 자른다. 창 크기가 바뀌면 다시 그린다.
- 정렬: 상태 범주(진행 중 → 할 일 → 완료), 그 안에서 갱신일 내림차순. 뷰를 고르면 뷰의 순서.
- 색: 상태 범주별 강조, 마감이 오늘 이전이면 경고색(extmark, 기본 강조 그룹에 연결).

키 (버퍼 지역)

| 키 | 동작 |
|---|---|
| `<CR>` / `o` | `jira/KEY.md` 열기(`open.open_key`) |
| `p` | 아래 분할 창에 미리 보기. 초점은 목록에 둔다. 줄을 옮기면 따라간다. 다시 누르면 닫는다 |
| `s` | 상태 거르기: 미완료(기본) → 전체 → 완료 순환 |
| `P`, `A` | 프로젝트·담당 거르기. 후보는 **지금 목록에 있는 값**에서 고른다(`전체` 포함) |
| `V` | 저장된 뷰 고르기(`views`에서. `—`는 뷰 없음) |
| `x` | 거르기 모두 지움 |
| `/` | Vim 기본 검색 그대로 |
| `c` `t` `a` `w` | 그 줄 일감에 댓글·전환·담당·워크로그(`jira.lua`의 함수) |
| `+` | 새 일감(지금의 `jira.create`. 2단계에서 양식으로 바꾼다). `n`·`N`은 검색의 다음·이전으로 남긴다 |
| `S` | 동기화 후 다시 그림 |
| `r` | 다시 읽어 그림(네트워크 없음) |
| `y` | 키를 레지스터에 복사 |
| `g?` | 도움말 |
| `q` | 닫기 |

- 고르기(`P`·`A`·`V`)는 `vim.ui.select`를 쓴다. fzf-lua·snacks 등이 있으면 그 선택 창이 뜨고, 없으면 기본 번호 목록이다. `ui.lua`에 `pick(prompt, items)` 이음매를 두어 시험에서 바꿔 끼운다.
- 쓰기 동작(`t`·`a`)이 성공하면(`on_done(0)`) `kb.py sync --key KEY`로 그 일감만 받아 다시 그린다. 실패·outbox 대기면 그리지 않고 기존 알림만 한다.
- 뷰를 고르면 상태 거르기는 "전체"로 바뀐다(뷰가 이미 거르기다). 프로젝트·담당 거르기는 뷰 위에도 적용된다. `"cached": false`인 줄은 흐리게 보이고, `<CR>`로 열면 기존처럼 먼저 받아 온다.
- 거르기 상태와 커서의 키는 세션 동안 기억한다. 다시 그려도 같은 키의 줄에 커서를 둔다.
- 캐시가 비었으면 빈 목록과 "S로 동기화하세요" 한 줄을 보인다.
- 화면이 없으면(`ui._can_prompt()` 거짓) 고르기는 취소로 본다. 버퍼 그리기는 화면 없이도 된다.

### 5.3 기존 것과의 관계

- Jira 메뉴(`<leader>kj`)는 그대로 두고 `l 일감 목록` 항목만 더한다. 메뉴 개편은 2단계.
- `results.lua`의 `<CR>`·`q` 규칙과 같게 맞춘다.
- `v`(보기)에서 키를 물을 때 목록에서 고르게 하는 일은 2단계로 둔다.

### 5.4 시험·문서

- `tests/test_issues.py`: 출력 스키마, 스텁·`_views`·범위 밖 제외, `--all`, `--view`, 깨진 front matter, `KB_AGENT=1` 허용, serve 경유.
- `tests/nvim/spec/issues_spec.lua`: 그리기(한글 폭 정렬), 거르기, 정렬, 커서 유지, 줄에서 `key_at_point`, 동작 후 다시 그리기, 빈 캐시, 화면 없음.
- 문서: `docs/USER-GUIDE.md` 6장(키 표, 새 절), `docs/README.md` 명령 표, `AGENTS.md` 명령, `docs/DECISIONS.md`에 `D-NV10`.

## 6. 내가 정한 것 (사용자가 말하지 않은 것)

1. 여는 키는 `<leader>kJ`. (`j`는 메뉴라 대문자로.)
2. 기본 거르기는 "미완료". 담당 기본은 "전체"다. 캐시 자체가 `jql_mine`(내가 담당·보고·지켜보는 것)이고, 도구는 "나"의 표시 이름을 모른다. "내 담당만"은 `A`에서 내 이름을 한 번 고르면 세션 동안 유지된다.
3. 한 줄 항목: 키·상태·우선순위·제목·담당·마감. 유형·스프린트·레이블은 미리 보기에서 본다.
4. 퍼지 검색 대신 `/`와 거르기 키.
5. 설정 저장은 세션 한정. 재시작하면 기본으로 돌아간다.
6. 새 일감 키는 `+`. `n`은 검색 다음 찾기로 남긴다.
7. 목록에서 다는 댓글은 빈 글에서 시작한다.
8. 뷰에만 있고 캐시에 없는 일감도 흐린 줄로 보인다(숨기지 않는다).
9. 기존 Jira 동작 함수에 선택 인수를 더한다. 인수 없이 부르는 지금의 동작은 바뀌지 않는다.

## 7. 구현자에게 맡기는 것

- `issues` 모듈의 Python 쪽 위치(`scripts/issues.py` 새 파일 또는 `jira_sync`의 함수 재사용).
- 강조 그룹 이름과 기본 연결.
- 미리 보기 창의 높이와 닫는 시점.
- 창 폭이 좁을 때 숨길 열의 순서(권장: 우선순위 → 담당 → 마감).
