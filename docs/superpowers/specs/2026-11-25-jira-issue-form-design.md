# Jira 쓰기 화면 2단계: 새 일감 양식과 후보 제안

2026-11-25. 상태: 승인 대기. 1단계(일감 목록, `D-NV10`) 위에 얹는다.

## 1. 의도

사용자의 말: "일감을 만들 때 선택할 수 있는 것들을 제안해 주지 못하고, 다 암기해야 한다."
새 일감·담당·워크로그·JQL·키 입력에서 **외워 치는 것을 없앤다**. 고를 수 있는 값은 Jira에서 받아 보여 준다.

## 2. 목표·비목표·실패 조건

목표
- 새 일감: 한 화면에서 모든 항목을 보고 고치고 한 번에 만든다.
- 유형·우선순위·담당자·컴포넌트·에픽 등은 고른다. 항목 목록과 **필수 여부는 Jira가 알려 주는 대로** 보인다(회사마다 다르다).
- 담당 지정(`a`)은 이름으로 찾아 고른다.
- 키를 물을 때(`v`·`c`·`t`·`a`·`w`) 캐시된 일감에서 고른다.
- 승격(`p`)도 같은 양식으로 연다(제목에 daily 줄을 채움).
- JQL(`q`)은 저장된 뷰와 최근 질의에서 고른다. 워크로그는 흔한 시간에서 고른다.

비목표: 기존 일감의 항목 편집, 첨부 올리기, 하위 작업 연결, 일괄 생성.

실패 조건
- 확인 없이 Jira에 쓴다. outbox를 거치지 않고 쓴다.
- 후보를 받지 못하면 일감을 못 만든다(오프라인이면 직접 쳐서 만들 수 있어야 한다).
- 양식을 닫거나 전송에 실패했을 때 쓴 글을 잃는다.

## 3. 접근 방식

화면

| 안 | 내용 | 장점 | 단점 |
|---|---|---|---|
| A (권장) | 편집 가능한 양식 버퍼. 항목 줄에서 `<CR>`로 고르기, 설명은 아래에 여러 줄, `C-c C-c`로 전송 | 한눈에 보임. 설명을 Vim으로 편집. 캡처 버퍼와 같은 조작 | 줄 구조를 지키는 코드가 필요 |
| B | 항목마다 차례로 묻는 마법사(`ui.pick` 연속) | 구현이 작음 | 되돌아가 고치기 어렵고 항목이 많으면 지루함. 지금 불편의 연장 |
| C | 브라우저로 Jira 생성 화면 열기 | 항목이 완전함 | 편집기를 떠남. 오프라인 불가, 승격 연결이 끊김 |

후보 받기

| 안 | 내용 | 단점 |
|---|---|---|
| 가 (권장) | 읽기 명령 `kb.py meta`가 Jira에서 받아 `.state/`에 캐시(하루). 오래됐으면 캐시를 먼저 보이고 뒤에서 새로 받음 | 하루 안에 바뀐 설정은 `r`로 새로 받아야 함 |
| 나 | 매번 Jira에 묻기 | 열 때마다 기다림. 오프라인 불가 |
| 다 | `config.yaml`에 손으로 적기 | 암기를 설정 파일로 옮긴 것일 뿐 |

## 4. 설계

### 4.1 Python

`kb.py meta` (읽기, `KB_AGENT=1` 허용, Jira를 부르므로 serve 대상 아님)
- `meta create PROJECT --json [--refresh]` → `{fetched_at, stale, issuetypes: [{name, fields: [{id, name, required, has_default, kind, allowed: [{id, name}]}]}]}`
- `meta users (--project PROJECT | --issue KEY) --query 글 --json` → `[{name, display}]` (`/user/assignable/search`, DC의 검색 인수는 `username`. 담당 지정은 `issueKey`로, 새 일감은 `project`로 묻는다. 최대 50명, 캐시하지 않음). 실패하면 캐시된 일감의 담당자·보고자 이름은 **표시 이름만** 알 수 있으므로 후보로 쓰지 않는다.
- Jira DC 8.4 이상: `/issue/createmeta/{project}/issuetypes[/{id}]` (쪽 나눔 처리). 404면 옛 `/issue/createmeta?expand=…`로 한 번 더 묻는다(8.4 미만). 둘 다 404면 `/project/KEY`로 확인해 "프로젝트가 없거나 볼 수 없음"을 알린다. 네트워크 오류면 전의 캐시를 `stale: true`로 낸다. 새로 받기에 실패해도 좋은 캐시를 덮지 않는다. 캐시도 없으면 기본 양식(유형 `Task·Bug·Story` 또는 직접 입력, 요약, 설명)만 낸다(`fallback: true`).
- `meta me --json` → 내 사용자명·표시 이름(`/myself`). 담당 후보 맨 위 "나"에 쓴다. 목록의 `A`에는 쓰지 않는다(목록은 표시 이름으로 거르므로 동명이인이 섞인다).

`act create` 확장
- 새 옵션 `--field ID=JSON`(반복). 알려진 항목의 모양(`priority: {name}`, `assignee: {name}`, `labels: [..]`, `components: [{id}]`, 선택 항목 `{id}`, 날짜 글자)을 편집기가 아니라 Python이 만든다: 편집기는 `--field components=["10001"]`처럼 id·글자만 보내고, `meta` 캐시의 항목 종류로 변환한다. 캐시에 없는 id는 거부한다(종료 4).
- `kind`는 `schema.system`·`custom`·`type`·`items`로 정한다. 지원: `text`, `textarea`, `number`, `date`, `datetime`, `option`, `options`, `priority`, `user`, `users`, `labels`, `components`, `versions`(단일·여러 값), `epic`(`gh-epic-link`). 그 밖(단계식 선택, 시간 추적, 상위 일감, 스프린트 등)은 `unsupported`.
- `act create`·`promote`에 `--json`: 마지막 줄에 `{record, state: done|pending|uncertain|failed|none, key, message}`. `none`은 기록이 남지 않음(토큰 없음, 설정 오류)이다.
- `promote --expect-line 해시`: 양식을 열 때의 줄과 다르면 거부한다(종료 4). 다른 줄을 찾아 옮기지 않는다.
- outbox payload에 `fields`(변환된 값)를 더한다. 전에 쌓인 기록(`fields` 없음)도 그대로 보낸다.
- 비밀값 검사(`refuse_secret`)는 `fields`에도 한다. 프로젝트·유형·요약·설명은 `--field`로 덮지 못한다.
- `promote`도 `--summary`·`--description`·`--field`를 받는다. `--summary`를 주어도 중복 판정(`line_hash`)은 원래 줄로 한다.

### 4.2 Neovim: 양식 `*work-kb-issue-form*`

```
 새 일감                         C-c C-c 만들기   C-c C-k 닫기   <CR> 고르기
 프로젝트 *   KB
 유형 *       Task
 요약 *       배포 스크립트 롤백 처리
 우선순위     High
 담당         김철수 (kim.cs)
 컴포넌트     API, 배치
 레이블       —
 마감         2026-11-30
 ─ 설명 ─────────────────────────────────────────
 여러 줄로 쓴다
```

- 필수 항목(`*`)은 먼저, 그 다음 흔한 항목(우선순위·담당·컴포넌트·레이블·마감·에픽), 나머지는 `g.`로 펼친다. 해당 유형에서 쓸 수 없는 항목은 보이지 않는다.
- 항목 줄에서 `<CR>`: 값이 정해진 항목은 `ui.pick`, 여러 값은 켜고 끄기를 반복, 글·날짜·숫자는 `ui.input`. 담당은 검색어를 묻고 결과에서 고른다("나"가 맨 위). 값 지우기는 `x`. 필수라도 Jira에 기본값이 있으면(`has_default`) 비워도 된다.
- 항목 줄은 직접 편집할 수 없다(설명 부분만 편집). `modifiable`을 커서 위치로 바꾸지 않고, 항목은 위쪽 읽기 전용 창, 설명은 아래 편집 창의 두 창으로 만든다.
- `C-c C-c`: 필수 항목이 비면 보내지 않고 그 줄로 간다. 다 차면 요약을 보이고 확인받아 `act create … --yes`로 보낸다.
- 결과는 종료 코드가 아니라 `--json`의 `state`로 판단한다.
  - `done`: 양식을 닫고 새 키를 알린다. 새 일감은 Python이 이미 받아 오므로 목록만 다시 그린다.
  - `pending`·`uncertain`: 기록이 outbox에 있다. 양식을 닫고 내용은 기억한 채, 다시 보내면 중복될 수 있음을 알린다(`uncertain`은 Jira에서 확인하라고 알린다).
  - `failed`·`none`: 양식을 그대로 두고 오류 글을 보인다. 고쳐 다시 보낼 때 앞의 `failed` 기록은 `act discard ID`로 치운다(새 하위 명령. `failed`만 되고 지우지 않고 `discarded`로 표시해 `--retry-failed`가 다시 보내지 않게 한다).
  - 출력에서 `state`를 읽지 못하면 `uncertain`으로 본다.
- `C-c C-k`로 닫아도 세션 동안 내용을 기억한다. 다시 열면 이어 쓸지 묻는다.
- 프로젝트·유형의 마지막 선택을 세션 동안 기본값으로 쓴다.
- 유형을 바꾸면 새 유형에도 있는 항목의 값만 남긴다.
- `unsupported` 항목은 "Jira 웹에서만"으로 보인다. 필수이고 기본값이 없을 때만 그 유형의 만들기를 막는다.
- 캐시가 오래됐으면 Lua가 `--refresh`를 뒤에서 돌린다. 끝나도 열린 양식은 바꾸지 않고 "새 후보를 받았습니다. `r`로 반영"만 알린다. `r`은 없어진 값을 지우고 무엇을 지웠는지 알린다.
- 버퍼는 `*work-kb-issue-form*`(항목)과 `*work-kb-issue-description*`(설명) 둘이다. 어느 쪽을 닫아도 둘 다 닫히고 내용은 기억된다.

### 4.3 다른 입력

- `a`: 사용자 검색 → 고르기. 받지 못하면 지금처럼 직접 친다.
- 키 묻기(`jira.jira_key`, 콜백으로 바꿈): 캐시된 미완료 일감을 "KB-12 제목"으로 고른다. 맨 아래 "직접 입력". 화면이 없거나 캐시가 비면 지금과 같다.
- `w`: `15m 30m 1h 2h 4h 8h`와 "직접 입력".
- `q`: 저장된 뷰(`kb.py issues --json`에 `view_jql: {이름: JQL}`을 더한다)와 이 세션의 최근 질의 10개, "직접 입력".
- `t`: 번호 입력 대신 `ui.pick`. 전환 목록 받기도 비동기로 바꾼다.
- `j` 메뉴: 화면 맨 아래 한 줄 대신 가운데 뜨는 창에 키와 설명을 세로로 보인다. 키는 그대로다.

`ui.pick`은 비동기일 수 있다. 위 동작은 모두 콜백으로 바꾸고, 처음에 정한 일감 키·daily 줄을 끝까지 쓴다(그사이 커서가 움직여도 바뀌지 않는다). 콜백 안의 사용자 오류도 traceback 없이 문구만 보이도록 공통 감싸개를 둔다.

## 5. 내가 정한 것

1. 항목은 하나하나 정하지 않고 Jira의 생성 정보(createmeta)를 따른다. 그래서 "실제로 채우는 항목"을 미리 묻지 않는다.
2. 후보 캐시는 하루. `r`로 새로 받는다.
3. 담당자 목록은 저장하지 않는다(개인 정보).
4. 에픽은 캐시된 일감에서 고르거나 키를 직접 친다(팀의 에픽이 캐시에 없을 수 있다). 스프린트는 이번 범위에서 뺀다(`unsupported`).
5. 확인 질문(y/n)은 남긴다.

## 6. 순서와 크기

프로젝트 크기다. 세 덩어리로 나누어 각각 쓸 수 있게 한다.
1. Python `meta`와 `act create/promote --field` (모의 Jira에 createmeta·사용자 검색 추가).
2. 고르기: `a`·키·`w`·`q`·`t`·메뉴 창.
3. 새 일감·승격 양식.

## 7. 확인할 수 없는 것

- 회사 Jira DC의 버전과 사용자 정의 항목. 모의 서버(9.17 형식과 옛 형식)로만 시험한다. 회사에서 `kb.py meta create <프로젝트>`를 한 번 돌려 확인한다.
