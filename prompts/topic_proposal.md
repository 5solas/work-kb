# 작업: 주제 제안 (T4)

입력은 최근 2주의 daily `## 기록` 전문과 이미 있는 주제 목록이다. 기록 줄 앞에는 `[L1]` 같은 줄 id와 날짜가 있다.

할 일: 여러 날에 걸쳐 되풀이되는 업무 주제 중, 따로 위키 페이지로 모아 두면 좋을 것을 제안한다.

규칙
- 한 번만 나온 일은 제안하지 않는다. 적어도 두 줄 이상의 근거가 있어야 한다.
- Jira 일감 하나나 사람 한 명은 주제가 아니다(이미 페이지가 있다).
- `name`은 짧은 명사구(2~20자). `[ ] # ^ | / \ : * ? " < >` 문자는 쓰지 않는다.
- 이미 있는 주제와 같으면 제안하지 않는다. 비슷한 주제의 다른 이름이면 `merge_with`에 기존 주제 이름을 그대로 쓴다. 아니면 `merge_with`는 null.
- `why`는 한 문장. `sample_sources`에는 근거가 된 줄 id만(입력에 있는 것, 2~5개).
- 제안할 것이 없으면 빈 목록을 쓴다. 많아도 5개까지.

출력: JSON 객체 하나만. 코드 블록이나 다른 글 없이 `{`로 시작해 `}`로 끝낸다.

{"proposals": [{"name": "캐시 설계", "why": "캐시 구조와 시각 저장 방식이 여러 날 논의되었다.", "sample_sources": ["L1", "L4"], "merge_with": null}]}
